## 【最新进展 · 2026-07-24 校订】AI 原生控制平面

### 已跑通的核心命题

`自然语言 → LLM → LIR → M-Token 字节码 → 执行` 这条链，**已用真实本地 Ollama 端到端跑通**
（不再是构造好的 LIR，而是模型自己生成的）。这是最难、最不确定的一关，已过。

- **接通断点**：新增 `python/MCP/lir_backend.py`，把论文分区里已验证的 `mir_compiler`
  （LIR 编译器）+ `backend_adapter`（PC 端参考 MVM）接进运行时。此前运行时只走 tool call，
  从未生成过 LIR，论文系统与线上系统是**断开**的——现已接通。
- **PC 资源设备化（路线 A）**：把文件/进程/网络抽象成带 `device_id` 的虚拟设备
  （file0=200, proc0=210, net0=220），复用现有 IOW/IOR + GTWAY 能力门控，MVM 一行未改，
  硬件与 PC 资源走同一套指令 → **MCU 与 PC 同构**。
- **文件槽真实执行器**：`python/MCP/pc_resources.py`，两阶段（先模拟演练、全通过才物化）
  + 沙箱目录 + 路径穿越拦截 + 参数隔离（真实路径来自服务端受信配置，不来自 LLM）。
- **MCP 工具**：`execute_lir_mcp`（纯模拟、零副作用）、`execute_lir_action_mcp`（真实文件写入）。
- **回归测试**：`python/MCP/test_lir_backend.py`，**15 个用例全绿**。
- **端到端冒烟**：`python/MCP/smoke_e2e.py`，qwen3:8b **3/3 通过**。

### 真实完成度地图（不高估）

| 能力 | 状态 | 真相 |
|------|------|------|
| 自然语言→LIR→字节码 | 🟢 通了 | 已端到端验证；但仅冒烟脚本，**真实服务链路(tool-router/WebUI)尚未接** |
| 控制继电器 | 🟡 模拟 | PC 上为模拟执行；真硬件需 ESP8266 |
| 控制计算机-文件 | 🟡 残缺 | 仅能在沙箱写"预设内容"；动态内容(如把读到的温度写入)未做 |
| 控制计算机-进程/网络 | 🔴 未做 | 仅到"拒绝执行"为止 |
| eBPF 策略平面（论文最硬原创点） | 🔴 未做 | 必须在 Linux；一行未写 |
| 打包 / 安装 / 服务化 | 🔴 不存在 | 目前是散装文件，无"安装"对应物 |
| 在 Linux 上验证 | 🔴 未做 | 全部在 Windows 验证 |

### 过程中的关键发现

1. **弱模型（8b）自修能力≈0**：收到结构化编译错误后原样重吐，无视纠错 →
   不能依赖运行时自修兜底，要靠 system prompt 前置引导。
2. **两类高频错误已在系统层根治**：中文 task 名（桥接层规范化，零语义风险）、
   retry 体语义（prompt 补规则+示例）。
3. **云端大模型需鉴权**（401 用不了）→ 产品约束：**必须对本地弱模型鲁棒**。

### 施工路线（产品优先，用户已选定）

- 阶段一：核心服务化——把验证过的 prompt + `execute_lir` 接进真实服务（tool-router/MCP）。
- 阶段二：把"操控计算机"做实——文件动态内容 → 进程 → 网络。
- 阶段三：搬到 Linux + eBPF 策略平面 PoC。
- 阶段四：打包成可安装、可开机自启的服务。

> 结论：核心命题已验证（阶段一起点），**不是终点**。"往 Linux 一装就完"不成立——
> "操控计算机"目前只有文件写一个残缺切口，且尚无"安装"对应物。

### 3.2 数据流

1. **用户输入** → Open WebUI → Tool Router
2. **AI推理** → Ollama (qwen3:32b) → Tool call生成
3. **工具调用** → MCP Server → Skills编排
4. **硬件控制** → Serial → ESP8266 → MVM执行
5. **结果返回** → 反向路径 → 用户界面

## 四、安全机制

### 4.1 已实现的安全特性

1. **熔断保护**
   - 连续失败阈值：3次（可配置）
   - 冷却时间：15秒（可配置）
   - 自动恢复机制

2. **审计日志**
   - 所有操作记录到 `data/mcp/audit.jsonl`
   - 包含时间戳、操作类型、结果
   - 支持最近事件查询

3. **继电器安全**
   - 最大持续时间限制：60秒（可配置）
   - 确认门禁机制
   - 自动回落保护

4. **VM安全**
   - 步数限制：1,000,000步
   - 调用深度限制：32层
   - 栈溢出/下溢检查
   - 内存越界检查
